Normal gifts can change presentation section without altering their financial category. Lucky section/category consistency is checked on the server.

SENDING ORDER
Server sums public.gift_transactions.quantity, not coin expenditure, button taps, phone-local counters or only newly added gifts. A combo of 99 counts as 99 delivered units per recipient. Multi-recipient transaction rows count once each; Lucky result rows are used only to exclude nonfinal/reversed outcomes, not added again. Reversal/manual-review markers are excluded. Equal quantities retain featured → configured order → coin price → stable UUID ordering. Zero-send gifts remain in the catalogue. Lists refresh on open/resume and after every confirmed send. This is refreshed server truth, not a continuous WebSocket feed of all other users' sends.
